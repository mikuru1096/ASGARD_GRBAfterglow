\begin{abstract}
Interpreting multiwavelength \grb\ afterglows requires a calculation that keeps blast-wave dynamics, particle transport, local photon fields, absorption, and observer projection in the same physical bookkeeping system.  Many public workflows provide efficient synchrotron light curves for structured jets, but fewer expose the intermediate electron, hadron, photon-field, and reverse-shock states needed to test feedback-dominated scenarios or to diagnose numerical failures.  We present \asgard, a Python and Fortran toolkit for \grb\ afterglow modeling and fitting.  The public interface constructs a physical model from jet, external-medium, radiation, numerical, observer, reverse-shock, and hadronic options, while the compiled kernels advance the radius-ordered dynamics, electron transport, synchrotron and synchrotron self-Compton emission, gamma-gamma absorption, one-dimensional hadronic transport, reverse-shock emission, polarization, and observer-frame projection.  The code stores the local state on the shock-radius grid and applies observer time only at the final projection stage, which prevents post-processing fixes from replacing local conservation or source-sink accounting.  We describe the API, numerical contracts, validation artifacts, and explicitly unsupported backend boundaries.  Reproducible figures generated from the repository demonstrate public light-curve and spectrum queries, one- and two-dimensional electron transport timing, shell-level hadronic feedback roles, magnetized reverse-shock diagnostics, secondary reverse-shock energy accounting, and runtime composition.  The present release is a code and methods baseline rather than a single-event fit; its formal hadronic path is one-dimensional, and chi-resolved hadronic feedback and inverse-Compton-mediated electromagnetic cascades remain outside the implemented contract.
\end{abstract}

\section{Introduction} \label{sec:intro}

Gamma-ray burst afterglows are produced when relativistic ejecta transfer energy to the circumburst medium and accelerate nonthermal particles.  The standard synchrotron framework links the blast-wave dynamics, electron distribution, spectral breaks, and observer-frame light curves \citep{Sari1998,Granot2002}.  Modern afterglow work also requires structured jets, off-axis viewing, inverse-Compton channels, reverse shocks, polarization, and in some cases hadronic emission or secondary-pair feedback.  These additions make the problem more than a mapping from parameters to a flux density: the calculation must track where each particle and photon source term lives, which coordinate it uses, and which quantities are projected to the observer only after local evolution has been solved.

Open-source astrophysical software has become central to reproducible inference.  Packages such as \texttt{afterglowpy}, \texttt{Astropy}, \texttt{Gammapy}, \texttt{MOSFiT}, and \texttt{naima} show that a code paper is most useful when it documents not only an interface, but also the physical assumptions, data products, validation paths, and limits of the implementation \citep{Ryan2020,Ryan2024,Astropy2022,Gammapy2023,Guillochon2018,Zabalza2015}.  For \grb\ afterglows, the public afterglow ecosystem already includes efficient structured-jet synchrotron models and hydrodynamic-calibrated light-curve prescriptions \citep{vanEerten2010,Ryan2020}.  The complementary need addressed here is a radius-resolved research toolkit in which intermediate electron, hadron, photon-field, reverse-shock, and observer states remain inspectable and tied to explicit numerical contracts.

\asgard\ is designed around that requirement.  The code uses Python for public model construction, orchestration, fitting, and data products, and Fortran for the high-cost dynamics, transport, radiation, and projection kernels.  Its central state is ordered by shock radius rather than by observer time.  Observer time enters through an \eats\ projection after local particle and photon evolution has been assembled.  This separation is important for feedback problems: Bethe-Heitler pair production, pair-synchrotron cascades, photopion photon survival, and inverse-Compton cooling must be converted to the same shell coordinate before they can be compared or coupled.

This paper makes four contributions.  First, it records the public API and internal state graph so that users can connect published figures to reproducible model calls.  Second, it gives the coordinate, grid, and source-sink contracts that define the electron, photon, hadronic, reverse-shock, and observer-projection stages.  Third, it maps each figure to source data and a specific decision value, following the practice of modern open-source astronomy code papers rather than presenting benchmark plots as decorative examples.  Fourth, it states unsupported backend boundaries explicitly, so future extensions must begin from a physical contract rather than from a silent approximation.

This paper documents the current code and methods baseline.  Section~\ref{sec:design} gives the software architecture and public interface.  Section~\ref{sec:physics} describes the implemented physical modules.  Section~\ref{sec:numerics} records the numerical contracts that define the kernels and state objects.  Section~\ref{sec:workflow} summarizes fitting, caching, parallelism, and reproducibility.  Section~\ref{sec:verification} presents reproducible figure-level validation artifacts.  Section~\ref{sec:limits} states the boundaries that are intentionally not implemented in this release.

\section{Software Design and Public Interface} \label{sec:design}

\subsection{Radius-first state model}

The central design claim of this manuscript is that a radius-ordered state chain can keep electron, hadron, photon, reverse-shock, and observer products in one reproducible \grb\ afterglow calculation.  The evidence is the public API smoke tests, build checks, benchmark artifacts, and source-data-backed figures presented here; the most important physical boundary is that formal hadronic feedback is currently one-dimensional.

Figure~\ref{fig:architecture} summarizes the design.  A user constructs a \texttt{Model} from public dataclasses for the jet, medium, observer, radiation, numerical grid, solver options, reverse shock, and hadronic options.  These objects are normalized to a \texttt{RuntimeConfig} and a \texttt{SimulationSetup}.  A solve then produces a \texttt{SolveState} containing dynamics, electron, photon-field, hadronic, reverse-shock, observer, and component objects.  Downstream products such as light curves, spectra, sky images, polarization curves, and fitting likelihoods are derived from that state.

\subsection{State objects and runtime chain}

The public query methods are \texttt{flux\_density\_grid}, \texttt{flux\_density}, \texttt{spectrum}, \texttt{flux}, \texttt{sky\_image}, \texttt{polarization}, and \texttt{details}.  The fitting interface uses the same state construction and projection path, so likelihood evaluation and standalone model queries are not separate physical implementations.  \asgard\ also records component-level fluxes, including forward-shock synchrotron and synchrotron self-Compton (SSC), reverse-shock synchrotron and SSC, cross-zone inverse-Compton terms when enabled, and hadronic components.

The main call chain can be written schematically as
\[
\begin{split}
&\texttt{Model.flux\_density\_grid}
\rightarrow \texttt{RuntimeConfig}
\rightarrow \texttt{SimulationSetup} \\
&\rightarrow \texttt{solve\_state\_from\_setup}
\rightarrow \texttt{project\_flux\_grid}
\rightarrow \texttt{FluxResult}.
\end{split}
\]
For fitting, \texttt{Fitter.loglike} compiles a parameter vector into the same model path, evaluates the requested data points, and computes the likelihood.  The code therefore has one physical forward model for plotting, diagnostics, and inference.

\subsection{Configuration boundaries}

The public objects are intentionally explicit.  A complete \texttt{Model} contains the jet, medium, observer, forward-radiation object, optional reverse-radiation object, numerical grid, observer grid, solver options, reverse-shock options, and hadronic options.  This makes the state of a figure or fit reproducible from the script that created it.  It also prevents a tutorial or fitting script from hiding important numerical choices such as \texttt{num\_radius}, \texttt{num\_electron\_gamma}, \texttt{num\_photon\_frequency}, \texttt{electron\_solver}, \texttt{geometry\_projection}, and \texttt{electron\_photon\_coupling}.

The boundary checks are part of the scientific contract.  A request for a user-defined medium kernel, wind \(k\ne2\), jet spreading in the current structured backend, thermal electrons outside the supported solver, or non-axisymmetric toroidal polarization is rejected before a high-cost kernel is launched.  These checks occur at system boundaries where the user has requested a combination without an implemented physical contract; they are not fallback paths.

\subsection{Terminology ledger}

The manuscript uses the following canonical terms.  \emph{Forward shock} refers to the blast wave propagating into the external medium.  \emph{Reverse shock} refers to the shocked ejecta region and its region-3 thermal state.  \emph{Shell-level} means a quantity is stored on the radius grid without resolving the downstream chi coordinate.  \emph{Chi-resolved} means that the electron distribution or projection uses the finite-thickness downstream coordinate \(\chi\).  \emph{Joint feedback} means the opt-in shell-level coupling of electrons, photon fields, formal hadronic transport, and secondary pairs.  \emph{Observer projection} means the \eats\ and Doppler mapping from local luminosity to \(\fnu(t_{\rm obs})\).

\section{Physical Modules} \label{sec:physics}

The implemented physical chain is
\[
{\rm ejecta}
\rightarrow {\rm shocks}
\rightarrow N_e,\ N_p,\ n_\gamma
\rightarrow L_\nu'
\rightarrow F_\nu(t_{\rm obs}).
\]
Each arrow is a state transformation with an explicit coordinate and unit contract.  The code is written so that a later observer-stage product cannot change an upstream local distribution.

\subsection{Dynamics, external media, and jet structure}

The forward shock supplies \(R_i\), \(\Gamma_i\), swept-up mass, external density, and observer-time mapping.  The default external media are a uniform interstellar medium,
\[
n_{\rm ISM}(R)=n_0,
\]
and a \(k=2\) wind,
\[
n_{\rm wind}(R)=3.0\times10^{35}A_\ast R^{-2}.
\]
Density jumps and injection events are represented as explicit model inputs.  For a spherical isotropic-equivalent patch, the swept-up mass obeys the local relation
\[
\frac{dM_{\rm sw}}{dR}=4\pi R^2 n(R)m_p .
\]
The internal Fortran dynamics may use its own integration variable, but downstream modules depend only on the emitted radius-ordered arrays.  In the adiabatic uniform-medium and wind limits, the expected trends \(\Gamma\propto R^{-3/2}\) and \(\Gamma\propto R^{-1/2}\) provide physical acceptance checks, not replacement equations for the numerical kernel.

Top-hat, Gaussian, and power-law jet profiles enter as initial angular distributions of isotropic-equivalent energy and initial Lorentz factor.  Structured-jet calculations aggregate angular patches through the observer projection.  This is not the same as a lateral-spreading dynamics backend; the current public boundary for spreading is stated in Section~\ref{sec:limits}.

\subsection{Electron injection, cooling, and transport}

Electrons are advanced on a logarithmic Lorentz-factor grid.  Shock injection is modeled as a normalized nonthermal source,
\[
Q_e(\gamma_e,R)=A_e(R)\gamma_e^{-p}
\exp\left(-\frac{\gamma_e}{\gamma_{\max}}\right)
H(\gamma_e-\gamma_m),
\]
with number and energy constraints set by the swept-up electrons, \(\epsilon_e\), the accelerated fraction \(\xi_N\), and the local dissipated energy.  In the asymptotic \(p>2\) limit,
\[
\gamma_m \simeq
1+
\frac{\epsilon_e}{\xi_N}
\frac{p-2}{p-1}
\frac{m_p}{m_e}
(\Gamma_{\rm rel}-1),
\]
while the implementation uses the exact normalization required near \(p\simeq2\) or finite high-energy cutoffs.

The electron equation in the radius coordinate is
\[
\frac{\partial N_e}{\partial R}
+
\frac{\partial}{\partial\gamma_e}
\left(\dot{\gamma}_{e,R}N_e\right)
=Q_{e,{\rm shock},R}+Q_{e,{\rm secondary},R},
\]
where
\[
\dot{\gamma}_{e,R}
=\frac{dt'}{dR}
\left(
\dot{\gamma}'_{\rm ad}
+\dot{\gamma}'_{\rm syn}
+\dot{\gamma}'_{\rm IC}
+\dot{\gamma}'_{\rm SSA}
\right).
\]
The one-dimensional solvers include \texttt{fullhide\_1d}, \texttt{slc1\_1d}, \texttt{charint\_1d}, \texttt{t2g1\_1d}, and \texttt{weno5\_1d}.  The two-dimensional solvers \texttt{fullhide\_2d} and \texttt{charint\_2d} add a downstream finite-thickness coordinate \(\chi\).  The default stable public path is \texttt{fullhide\_1d}; two-dimensional transport and chi-resolved projection are opt-in paths used when the finite shell width is part of the hypothesis being tested.

\subsection{Synchrotron, self-absorption, and SSC}

The local turbulent magnetic field is tied to the shocked internal energy density,
\[
\frac{B'^2}{8\pi}=\epsilon_B u'.
\]
The synchrotron luminosity is computed from the electron spectrum and the single-particle kernel,
\[
L'_{\nu'}=\int N_e(\gamma_e)P'_{\nu'}(\gamma_e,B')\,d\gamma_e .
\]
Synchrotron self-absorption is handled as an optical-depth and survival-factor problem before observer projection.  In chi-resolved projection, finite-thickness cells use a cell-averaged survival factor rather than assigning all emission to a single face of the cell.

SSC has two separate roles: it is an observer photon component and an electron cooling term.  In numerical IC cooling mode the same seed photon field must be used for the electron loss and photon-emissivity budget.  A run that enables SSC photons but chooses a simplified cooling mode is therefore a different physical approximation from a run that closes the IC loss with the local photon field.

\subsection{Local photon fields and absorption}

The photon field is represented separately from observer luminosity.  If a local luminosity is used as a target photon field, the conversion requires shell geometry and an escape time,
\[
u'_{\nu'} \simeq \frac{L'_{\nu'} t'_{\rm esc}}{V'},
\qquad
n'_{\epsilon'}=\frac{u'_{\epsilon'}}{\epsilon'} .
\]
This distinction is required because an observer-side luminosity is not automatically a local target photon density.  SSC cooling and emission, gamma-gamma absorption, photopion targets, Bethe-Heitler photon losses, and pair-synchrotron feedback require explicit shell geometry, escape-time, absorption, and variable-conversion factors before they can be coupled.

Gamma-gamma absorption is treated as a photon survival and secondary-pair source problem.  When \texttt{pair\_cascade\_iterations>1}, the current implementation follows a shell-sequence gamma-gamma pair/synchrotron cascade: absorbed high-energy photons produce pairs, pairs radiate synchrotron photons, and that radiation contributes to subsequent shell-level photon fields.  The present code does not close an IC-mediated electromagnetic cascade.

\subsection{Hadronic transport and joint secondary feedback}

The formal hadronic path uses a one-dimensional shell contract.  Proton injection and transport can be written as
\[
\frac{\partial N_p}{\partial R}
+
\frac{\partial}{\partial E_p}
\left(\dot{E}_{p,R}N_p\right)
=Q_{p,R}+Q_{p,{\rm reinj},R},
\]
with loss terms from adiabatic evolution, proton synchrotron, photopion interactions, Bethe-Heitler pair production, and \(pp\) interactions when enabled.  Proton synchrotron, photopion photons, secondary radiation, and neutrinos are observer products or diagnostics unless a formal source or sink term is explicitly returned to the local photon/electron state.  The photopion operator follows the response-function approach of \citet{Hummer2010}.

In joint feedback mode, the coupled electron source is restricted to explicitly modeled secondary spectra,
\[
Q_{e,{\rm secondary},R}
=Q_{e,{\rm BH},R}
+Q_{e,pp,R}
+Q_{e,\gamma\gamma,R}.
\]
Photopion and Bethe-Heitler photon losses act through formal survival or loss terms.  If a process returns only a luminosity, it remains an output component and is not promoted to a feedback source.  This is why the hadronic section of the public API contains both process switches and a separate \texttt{electron\_photon\_coupling} setting.

\subsection{Reverse shock, secondary reverse shocks, and polarization}

The reverse-shock baseline includes electron synchrotron radiation, reverse-shock SSC, forward/reverse cross-zone IC, optional upstream magnetization, and optional reverse-shock hadronic branches.  The reverse-shock electron injection scale is tied to the shock-front relative Lorentz factor
\[
\gamma_{34}=\Gamma_3\Gamma_4(1-\beta_3\beta_4),
\]
not to a forward-shock average Lorentz factor.  The turbulent magnetic field uses the region-3 thermal state \(U_3/V_3\),
\[
B'_{3,{\rm turb}}=\sqrt{8\pi\epsilon_{B,3}U_3/V_3},
\]
and optional upstream magnetization adds an ordered component,
\[
B'_3=\left[(B'_{3,{\rm turb}})^2+(B'_{3,{\rm ord}})^2\right]^{1/2}.
\]
The \(\sigma \rightarrow 0\) limit is a validation boundary: it must recover the unmagnetized baseline.

Density-jump-triggered secondary reverse shocks are treated as separate branches tied to the density enhancement, local dissipated energy, and branch reservoir.  The branch does not duplicate pre-existing forward-shock electron radiation.  Polarization is attached only to synchrotron-emitting branches; non-synchrotron components are not mixed into Stokes parameters.

\section{Numerical Contracts} \label{sec:numerics}

\subsection{Radius coordinate and rate conversion}

The local evolution coordinate is shock radius \(R\).  For a shell with Lorentz factor \(\Gamma\) and velocity \(\beta c\),
\[
  \frac{dt'}{dR} = \frac{1}{\beta \Gamma c}.
\]
Any comoving rate in units of \({\rm s}^{-1}\) must be converted through this factor before entering a radius-coordinate transport equation:
\[
\lambda_R=\lambda'\frac{dt'}{dR},\qquad
Q_R=Q'\frac{dt'}{dR},\qquad
\dot{\gamma}_R=\dot{\gamma}'\frac{dt'}{dR}.
\]
This rule applies to electron cooling, proton losses, secondary injection, and photon absorption.  It is also the reason joint electron-photon-hadron feedback is not implemented as an observer-time post-processing correction.  The observer time
\[
t_{\rm obs}=(1+z)\left(t_{\rm lab}-\frac{R\mu}{c}\right)
\]
contains geometric delay and is therefore not an interchangeable step variable for local microphysics.

\subsection{Particle and photon grids}

Electron and proton spectra use logarithmic grids.  If \(x=\log_{10}\gamma\), the transported cell content is \(dN/dx\), not \(dN/d\gamma\).  Conversions therefore carry the Jacobian
\[
  \frac{dN}{d\gamma} =
  \frac{1}{\gamma \ln 10} \frac{dN}{dx}.
\]
The same bookkeeping applies to frequency grids: \(L_\nu d\nu = \widetilde{L}_{\ln\nu} d\ln\nu\).  The implementation keeps these conversions at the kernel boundaries and in state assembly, so that observer projection receives luminosities with the expected units.

\subsection{Finite-volume electron update}

The default one-dimensional electron solver advances the conservative variable \(N_x=dN/dx\) with an upwind finite-volume form,
\[
\frac{\partial N_x}{\partial R}
+
\frac{\partial}{\partial x}(v_x N_x)
=Q_x,
\qquad
v_x=\frac{1}{\gamma\ln10}\frac{d\gamma}{dR}.
\]
Across a shell step \(\Delta R_i\), the implicit update can be written schematically as
\[
N_{x,k}^{i+1}
=
N_{x,k}^{i}
-
\frac{\Delta R_i}{\Delta x_k}
\left(F_{k+1/2}^{i+1}-F_{k-1/2}^{i+1}\right)
+
\Delta R_i Q_{x,k}^{i+1}.
\]
For cooling-dominated problems \(v_x<0\), so the upwind stencil moves particles from high to low Lorentz factor.  The purpose of the implicit form is to handle stiff cooling without clipping or smoothing the output spectrum.  Other registered solvers, including characteristic and WENO paths, are used as method comparisons for break frequencies, high-energy cutoffs, and grid sensitivity.

\subsection{PhotonFieldState and joint feedback}

\texttt{PhotonFieldState} is the numerical interface between leptonic radiation and hadronic or absorption processes.  It stores seed fields for forward synchrotron photons, SSC/IC cooling, hadronic targets, and absorption targets.  The key transformation is
\[
L_\nu \rightarrow u_\nu \rightarrow n_\epsilon,
\qquad \epsilon=h\nu,
\]
with the per-frequency to per-energy conversion
\[
n_\epsilon=\frac{n_\nu}{h}.
\]
This contract is what allows IC cooling, SSC emissivity, photopion targets, Bethe-Heitler losses, and gamma-gamma absorption to be compared in one shell sequence.

The default \texttt{separated} chain solves the primary electron distribution, builds the photon field, and then computes hadronic or absorption diagnostics.  The opt-in \texttt{joint} chain performs a fixed internal feedback loop:
\[
\begin{array}{c}
\text{primary }N_e \rightarrow n_\gamma \rightarrow N_p,\ Q_{e^\pm},\ \Lambda_\gamma \\
\rightarrow \text{coupled }N_e \rightarrow \text{rebuilt }n_\gamma .
\end{array}
\]
The current public boundary requires \texttt{fullhide\_1d}, the formal \texttt{am3\_1d} hadronic path, Bethe-Heitler enabled, the Hummer photopion response, numerical IC cooling, and fixed electron substeps.  Unsupported combinations error at configuration time rather than switching to a separated calculation.

\subsection{Observer projection}

The observer stage maps local comoving luminosities to \(\fnu(t_{\rm obs})\) using Doppler factors, redshift, luminosity distance, and \eats\ interpolation.  With
\[
\delta=\frac{1}{\Gamma(1-\beta\mu)},
\]
the frequency transformation is
\[
\nu_{\rm obs}=\frac{\delta}{1+z}\nu'.
\]
The implementation variable named \texttt{doppler} corresponds to \(D=\delta^{-1}\), so the code naturally contains \(D^{-3}\) and \(\nu'=(1+z)D\nu_{\rm obs}\).  The chi-resolved kernel applies only to forward-shock synchrotron plus synchrotron self-absorption in the current release.  SSC, hadronic components, and pair cascades remain shell-level contributions unless a future physical contract defines their chi-local photon fields, particle densities, feedback, and projection.

\section{Fitting, Parallelism, and Reproducibility} \label{sec:workflow}

\subsection{Fitting path}

\asgard\ fitting is deliberately thin.  A data set supplies \(\{t_i,\nu_i,F_{\nu,i},\sigma_i\}\), and a parameter vector \(\boldsymbol{\theta}\) is written into explicit \texttt{Model} fields through \texttt{Param} paths.  The likelihood used by the public fitter is
\[
\ln {\cal L}(\boldsymbol{\theta})
=-\frac{1}{2}\sum_i
\left[
\frac{F_{\nu,{\rm model}}(t_i,\nu_i|\boldsymbol{\theta})-F_{\nu,i}}
{\sigma_i}
\right]^2 .
\]
There is no hidden outlier rejection, error inflation, or separate fit-only forward model.  Data-unit conversion, upper-limit treatment, and sample selection are system-boundary responsibilities.  If a fit produces non-smooth light curves, discontinuous spectra, or parameter trajectories pinned to unphysical boundaries, the expected workflow is to inspect the dynamics, electron spectra, photon fields, and projection state rather than to modify the likelihood.

\subsection{Caching and parallel execution}

The \texttt{Model} object can reuse an unchanged solve state for repeated observer queries.  This is a runtime optimization, not a physical approximation.  Benchmark reports therefore distinguish cold solve time from warm query time.  Structured-jet calculations may distribute work over angular patches, single-patch kernels, or nested outer/inner OpenMP modes depending on the backend.  The code documentation records the thread count and grid configuration because small grids can be dominated by parallel overhead while high-dimensional transport can be electron-kernel dominated.

\subsection{Reproducible figure contract}

All six paper figures are generated by a single Python/matplotlib entry point, \texttt{tests/generate\_paper\_figures.py}.  Each figure writes CSV source data to \texttt{paper/source\_data/} and exports SVG, PDF, and TIFF.  The figures are not a low-information ablation grid: each one answers a specific question about architecture, public queries, transport/projection cost, hadronic feedback semantics, reverse-shock diagnostics, or runtime composition.  Existing output-directory plots are not used as manuscript evidence unless they can be reproduced through the formal paper figure entry.

\section{Limitations and Unsupported Boundaries} \label{sec:limits}

Several public options are intentionally bounded.  Jet spreading is not implemented in the current structured/top-hat backend.  User-defined \texttt{Medium} kernel dispatch is not supported; the compiled density contract covers uniform media and \(k=2\) winds.  Wind profiles with \(k \ne 2\) are rejected rather than silently approximated.  Thermal electrons are supported only in the \texttt{fullhide\_1d} branch.  Toroidal polarization is not supported for non-axisymmetric jets.

The formal hadronic path is one-dimensional and shell-level.  A chi-resolved hadronic implementation would require chi-local photon fields, hadron densities, secondary feedback, and observer projection before it could be physically meaningful.  Similarly, the current pair cascade is a gamma-gamma pair/synchrotron branch.  An inverse-Compton-mediated electromagnetic cascade would require additional photon and pair source-sink equations and an energy-budget benchmark.  These omissions are scientific boundaries, not missing fallback code.

The manuscript also does not claim that the validation examples exhaust the physical model space.  They are targeted tests selected because they answer decisions about public query behavior, coordinate contracts, source-sink accounting, reverse-shock diagnostics, and runtime composition.  Low-information sweeps that would only repeat known unsupported cases are deliberately not included.

\section{Summary} \label{sec:summary}

\asgard\ provides a radius-resolved \grb\ afterglow toolkit that exposes public model queries while preserving inspectable intermediate states for dynamics, electrons, photon fields, hadrons, reverse shocks, polarization, and observer projection.  The code design separates Python orchestration from Fortran numerical kernels and keeps local feedback on the shock-radius grid before observer-time projection.  The present paper records the method contracts, source-data-backed figures, validation checks, and explicit backend limits for the current baseline.  This makes \asgard\ a reproducible platform for afterglow modeling work where the numerical path and physical boundary conditions must be auditable, not only a generator of final light curves.
